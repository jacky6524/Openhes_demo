# OpenHES Demo — 開發進度與換機交接

> 更新日期：2026-11-03　｜　版本：`package.json` v0.1.0
> 用途：把這包帶到另一台主機繼續開發時，先讀這份。

---

## 一、換機三步驟

```powershell
# 1. 把資料夾複製過去（要帶哪些見第三節）
# 2. 在專案根目錄安裝相依套件
npm install

# 3. 啟動開發伺服器（會自動開瀏覽器，port 5173）
npm run dev
```

沒有其他前置作業——不需要資料庫、不需要後端、不需要網路。**全部資料都是前端 mock**。

## 七、重要設計決定（別誤改）

1. **`src/data/dcuMetrics.ts` 是 API 替換接縫。** 衍生指標一律走這個入口，不要自己遍歷電表陣列。之後接真 API 只要換這一層。
   目前對外的四個函式：`dcuStat()`、`dcuRange()`、`misassignedOfDcu()`、`clearMetricsCache()`。
2. **`tokens.ts` 是色彩的單一真實來源**，`tailwind.config.js` 是它的鏡像，改一邊要同步另一邊。
   2026-08-27 起**這兩份又都是 `openhes-front/shared/assets/color.css` 的鏡像**——三邊要一起改。
   `tokens.ts` 每個常數上方都註明了對應的前端 semantic token。
3. **色彩使用規則**（2026-08-27 隨品牌色改版調整）：紅色給告警與越界值；紫色系給量級／趨勢；藍/青給正常狀態。
   品牌色已從玫瑰 `#C23B52` 換成前端的 HES 紅 `#c10007`，所以**品牌色與告警紅同屬紅系**，
   原本「紅色只給告警」的規則不再成立——這是為了跟前端一致而刻意放棄的，不是疏漏。
   另外前端 dashboard 自己還留著幾個區域色（麵包屑 hover `#b83257`、目前層級 `#241f23`、
   浮框邊框 `#eadfe1` 等），這些**不是**全域 token；prototype 照抄它們是為了畫面一致，別換成 brand token。
4. **趨勢箭頭顏色**：惡化才紅，改善或持平都是黑色，不用綠色。
5. **關係地圖會納入「自己在範圍外、但收容電表跨界落入範圍」的 DCU，故障地圖不會**——這是刻意的設計差異，不是 bug。
6. **兩張地圖常駐、只切 `visibility`**，不要改成條件渲染——原本每切一次頁籤要 300–500ms 重建 WebGL，會白畫面。
7. **地圖著色一律綁 LP 讀表率**，不隨上方 KPI 卡選取而變。
8. 系統總覽散點圖的 Y 軸固定 LP，不隨 `selectedKpi` 改變。
9. **日期一律 `YYYY/MM/DD`**（含時間 `YYYY/MM/DD HH:mm[:ss]`；2026-11-04 業主要求全站統一，同正式版 `formatUpdateTime`）。
   - 只用來顯示／排序的資料來源**直接產生斜線**：`dcuFleet.stampOf`、`permissions.stampOf`、`usePerm.now`、`statusThresholds`、`mdmsUpload.fmtStamp`（預設 sep `/`）、`meterDetail.rowTime`、`meterProfile`、`dcuLogs`、`dcuListPage`、`meterInfo`、StatsReport／RegistrationConflict／DeviceRecord／InstantQuery 的 mock、各「更新時間」常數、電表詳細資料與 DCU 詳細資料的唯讀區間。圖表軸的 `MM/DD`、`HH:mm` 本來就是斜線或不含日期。
   - **會和 `<input type="date">` 比大小的資料維持 `YYYY-MM-DD`**，在畫面上用 `fmtDate()`（`lib/format.ts`）轉：即時讀表的 `readTasks`（資料時間／排程時間篩選）。`StampLines` 也會自動套 `fmtDate`，兩種來源都顯示成斜線。
   - **不要改**：日期輸入框的值與預設值（瀏覽器規定 `YYYY-MM-DD`／`YYYY-MM-DDTHH:mm`，顯示樣式跟作業系統走，字串改不了）、`DateTime15`／`addMonths`、`mdmsUpload.parseLocal`、DeviceRecord `_date` 與 StatsReport `dataDate`（隱藏的篩選欄）。
   - 同一欄的資料若來自兩個產生器（例：功能項目管理的 `updatedAt` 來自 permissions 種子與 `usePerm.now`），兩邊要同時改，否則字串排序會亂。
